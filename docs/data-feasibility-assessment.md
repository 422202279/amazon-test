# 数据获取与落地评估

更新时间：2026-07-02

## 1. 结论先说

### 产品数据

产品数据可做，而且可以先做得比较稳。

优先级建议：

1. 内部产品汇总表
2. 卖家精灵产品导出
3. 卖家精灵历史销量 / 历史销售额 / 历史价格导出
4. 后续再补低频页面校验

这条链路最大的优点是：

- 不依赖付费新接口
- 不需要高频抓取
- 能较稳定覆盖 Amazon 多站点
- 能先把产品列表、店铺对比、趋势分析做起来

### 评论数据

评论数据不能按“官方 API 一定能拿到完整评论正文、图片、评论人、星级时间”来设计。

当前更现实的设计应该是三层：

1. **V1 可落地**：评论 Excel / CSV 手工导入 + 后台人工校验
2. **V1.5 半自动**：根据产品链接或评论页链接，做低频页面抓取任务
3. **V2 条件成熟再扩展**：研究各平台官方能力、低频同步、失败重试和代理策略

也就是说：

- 产品模块可以先做成高可靠
- 评论模块要做成“多来源兼容”，不能押注单一自动化来源

## 4. 评论数据到底能不能自动化拿

### Amazon

官方有 Selling Partner API，但它并不是给你拉完整前台评论明细用的。

能用于产品、目录、报表、订单、库存等官方卖家业务流。

另外我查到 Amazon 官方还有 `Customer Feedback v2024-06-01`，但它偏向**反馈主题 / 趋势**，不等于你要的那种“逐条评论正文 + 图片 + 星级 + 站点 + 评论时间”的完整评论抓取。

这意味着：

- **不能把 Amazon 评论模块建立在“官方评论明细 API”这个假设上**
- 更靠谱的是：页面低频采集 + 导入补充 + 人工校验

### Coupang / Naver

这两边官方确实都有商家 API / Commerce API，但我目前没有在官方公开文档中确认到能稳定拿到你需要的“完整评论明细 + 图片证据 + 可持续批量拉取”的公开接口。

所以对韩国站，我建议：

- **V1 继续手工导入优先**
- 产品数据先统一进产品主表
- 评论做导入接口和预留采集任务，不要第一阶段强依赖自动抓取

## 5. 云部署后能不能自动跑

### 产品数据

可以。

云上最容易落地的是：

1. 人工上传产品表
2. 系统自动解析
3. 自动写入 SQLite / 后续可切 PostgreSQL
4. 自动生成产品趋势和店铺对比结果

### 评论数据

云上“能不能跑”分两种情况：

#### 情况 A：基于导入

完全能跑，而且最稳。

#### 情况 B：基于网页自动抓取

能做，但要保守设计：

- 低频任务
- 限速
- 失败重试
- 人工复核
- 不承诺所有站点都长期稳定

我不建议你把整个项目价值建立在“所有评论都能云端自动无痛抓取”上。

更合适的设计是：

- 先把产品和趋势做准
- 评论用导入 + 半自动补充
- 自动抓取只是加速器，不是唯一入口

## 6. 图片要不要存很大

不建议。

对于你这种“低成本、低配云服务器、几个人使用”的场景：

- 产品主图只保留原图 URL 或下载中尺寸缩略图
- 评论图片优先保存缩略图 URL、原图 URL、哈希、抓取时间
- 真正落盘时只缓存必要缩略图

建议策略：

1. **默认不落原图**
2. **只存 URL、宽高、抓取时间、来源**
3. **需要证据固化时，再下载单张评论图**
4. **前端列表只展示压缩缩略图**

这样最省磁盘，也最适合低配云服务器。

## 7. 报告生成在没有 Codex 能力时还能不能做

可以，但能力分层要分清。

### 不依赖 Codex 也能做的

- 固定模板 Markdown 报告
- 固定模板 Word / Excel 导出
- 店铺对比统计
- 问题分类统计
- 趋势图和表格摘要
- 历史生成记录 / 导出记录

### 依赖 AI 或人工分析的

- 自动生成深度归因结论
- 自动写高质量自然语言整改建议
- 自动判断复杂共性问题

所以更稳的落地方式是：

- 先把报告系统做成模板化、结构化、可导出
- AI 分析能力作为增强项

## 8. 第一阶段开发建议

不要一次把所有模块一起压满。

建议按 4 小时内一个阶段拆：

### 第 1 阶段（3~4 小时）

- 后端骨架
- SQLite 模型
- 店铺 / 产品基础表
- 产品导入预览
- 产品主表 API

### 第 2 阶段（3~4 小时）

- 店铺对比与趋势模型
- 历史销量 / 历史价格导入
- 产品详情 API
- 报告中心基础记录

### 第 3 阶段（3~4 小时）

- 评论表结构
- 评论导入
- 问题分类
- 供应商整改任务

### 第 4 阶段（2~4 小时）

- 评论半自动抓取任务
- 失败记录
- 数据校验
- 导出与模板报告
