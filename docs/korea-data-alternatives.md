# 韩国站替代方案

更新时间：2026-07-03

## 结论

`Coupang / Naver` 不适合作为云端公开页面自动抓取主链路，但并不代表韩国站做不了。

最现实、最低成本、最稳的方案是：

1. 优先走官方卖家后台 / 官方 API / 后台导出
2. 没有稳定导出时，先建立产品主档
3. 再做低频手动更新或半自动补录
4. 不把公开页面抓取当核心依赖

## Naver 的替代方案

### 1. 官方后台导出

已有外部教程明确提到：

- Smart Store Center 可在商品管理里使用 `Excel Download`
- 这意味着产品主档导出是可行路线

### 2. 官方 API

已有资料显示：

- Naver Smart Store 存在 Commerce API 路线
- 需要开发者申请、账号权限、客户端信息以及白名单 IP

### 3. 可行落地建议

V1 推荐顺序：

1. 先用后台导出建立主档
2. 再评估是否申请 Commerce API
3. 评论先走人工导入 / 低频补录

## Coupang 的替代方案

### 1. 卖家后台 / WING

官方 Global Marketplace 和 WING 资料已明确：

- 已有卖家门户
- 有 API integration 方向
- 也有服务商网络可接

这说明：

- Coupang 不适合走公开商品页抓取
- 更适合走卖家侧后台或集成方式

### 2. 可行落地建议

V1 推荐顺序：

1. 先从 WING / 卖家侧拿产品数据
2. 如果没有导出工具，就先维护一次产品主档
3. 后续只增量补新 SKU 和关键字段

## 如果你现在没有现成导出工具

那就不要卡在“等一个完美自动化工具”。

最省钱的替代方案是：

### A. 建一次韩国站产品主档

字段最少先录：

- 平台
- 店铺
- 站点
- 产品标题
- 商品链接
- 内部 SKU
- 平台商品 ID / 自定义识别码
- 当前价格
- 当前评分
- 当前评论数

### B. 后续只更新变动字段

不用每次全量导入，只补：

- 新增商品
- 价格变化
- 评分变化
- 评论数变化

### C. 评论模块先低配运行

韩国站评论先不要追求“全量自动回收”。

先做：

- 评论总数
- 评分
- 重点差评样本
- 图片 / 视频证据缩略图

## 我建议的 V1 韩国站方案

### Naver

- 产品：后台导出优先
- 补充：能申请 API 再接 API
- 评论：人工导入 + 重点样本录入

### Coupang

- 产品：卖家侧数据优先
- 补充：如果能找到官方集成方式，再做对接
- 评论：先做样本和统计，不做全自动明细

## 为什么这是最优方案

原因很简单：

- 成本最低
- 对最低配云服务器最友好
- 不依赖高风险抓取
- 后面还能逐步升级

## 后续开发影响

系统要支持：

1. 韩国站单独导入模板
2. 手动更新按钮
3. 定时低频同步入口
4. 数据来源标记
   - 官方导出
   - 官方 API
   - 人工补录
   - 页面校验
