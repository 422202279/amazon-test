# 数据更新策略

更新时间：2026-07-03

## 目标

系统要尽量减少手工导入，但不能为了省事去依赖不稳定、不可持续的抓取方式。

所以这套系统的数据更新原则是：

1. 能稳定导入的，优先导入
2. 能低频公开校验的，做校验补充
3. 拿不到的，不编造
4. 评论数据先做多来源兼容，不押注单一自动抓取

## 一、产品数据

### 1. 每天自动更新的目标数据

优先每天更新一次：

- 店铺列表
- 产品主档
- 价格
- 评分
- Review 总数
- 月销量
- 月销售额
- BSR
- BuyBox / 卖家数
- 历史价格 / 历史销量趋势

### 2. 推荐来源

主来源：

- 卖家精灵导出产品表
- 卖家精灵导出历史销量 / 历史销售额 / 历史价格表
- 内部产品汇总表

辅助来源：

- Amazon / Coupang / Naver 产品公开页面链接

### 3. 云服务器上可持续能力

可持续：

- 定时读取人工上传的 Excel
- 自动解析入库
- 自动汇总趋势
- 自动生成固定模板报告

不建议依赖：

- 云服务器长期模拟登录卖家精灵
- 高频页面抓取
- 非公开接口

### 4. 韩国站当前实测结果

2026-07-03 直接从服务端访问你给的两个韩国链接时：

- Coupang 产品链接返回 `403 Access Denied`
- Naver SmartStore 产品链接返回 `429`
- Coupang 店铺页可以返回 `200`，但更像前端壳页面，不适合作为稳定批量抓取依据

这说明：

- 这两个链接当前更适合作为“人工核对入口”
- 不适合作为云服务器稳定定时抓取主链路
- 韩国站产品数据在 V1 仍应优先走导入或低频人工校验

### 5. Amazon 当前补充实测

2026-07-03 抽样验证了美国、英国、德国、日本商品页样本。

商品页可直接拿到的字段至少包括：

- 标题
- ASIN
- 评分
- 评论总数
- 面包屑类目
- 卖点 bullet
- 主图

但评论页直接请求不稳定：

- 部分站点虽然返回 `200`
- 返回内容中未稳定出现评论块
- 英国、日本样本出现 `SSL EOF`

所以 Amazon 评论明细在 V1 也不应承诺“全自动稳定全量抓取”。

## 二、评论数据

### 1. 第一阶段结论

评论数据先不要设计成“每天云端自动把所有评论完整抓回来”。

原因很简单：

- Amazon 官方能力不等于完整评论明细接口
- 韩国站评论链路更不稳定
- 云端没有你本机现在这种人工登录条件

### 2. 推荐方案

评论模块分三层：

#### A. 主方案

人工导出评论数据后导入系统

#### B. 半自动方案

系统维护：

- 产品链接
- 评论页链接
- 最近抓取时间
- 最近抓取结果

然后做低频抓取尝试，只抓：

- 星级
- 评论标题
- 评论正文
- 评论时间
- 图片链接

如果失败，保留失败记录，不影响系统主体运行。

#### C. 校验方案

对于重点产品：

- 记录页面评分
- 记录评论总数
- 与导入评论数比对

如果两者差异过大，就提示“评论导入可能不完整”。

## 三、更新频率建议

### 每天早上 1 次

建议时间：

- 06:30 到 08:00

执行顺序：

1. 导入最新产品主表
2. 导入历史销量 / 销售额 / 价格
3. 更新产品趋势
4. 更新店铺对比结果
5. 尝试执行低频评论抓取任务
6. 生成异常摘要

## 四、哪些字段可以直接依赖，哪些只能辅助参考

### 可以作为核心字段

- ASIN
- 父 ASIN
- 店铺
- 平台
- 站点
- 产品链接
- 商品标题
- 价格
- 评分
- Review 总数
- 月销量
- 月销售额
- BSR
- 上架时间
- 卖家数
- BuyBox 卖家

### 作为辅助字段

- 留评率
- 广告流量
- 关键词数量
- 毛利率
- A+ / 视频 / 品牌广告标记

### 不应伪造或强依赖

- 全站完整评论明细自动抓取
- 所有站点统一评论图片获取成功率
- 韩国站评论完整自动化

## 五、准确性校验

后端后续必须补 3 类校验：

1. 结构校验
2. 主键校验
3. 页面校验

### 结构校验

- 必填字段是否存在
- 列名是否变化
- 数值格式是否异常

### 主键校验

- ASIN 是否重复
- 店铺 + ASIN 是否重复
- 月度趋势数据是否重复导入

### 页面校验

对少量重点产品，低频打开页面校验：

- 价格
- 评分
- Review 数
- BuyBox 卖家

如果和导入数据差异明显，提示人工复核。

## 六、图片策略

产品图和评论图都不建议保存大图到云服务器。

推荐：

- 默认只存链接
- 页面只用缩略图
- 需要证据时再下载单张图

建议控制：

- 单张缩略图尽量在 `200KB ~ 500KB`
- 默认不批量下载原图
- 整个系统累计下载量严格控制在 `1GB` 以内

这样更适合低配云服务器。
